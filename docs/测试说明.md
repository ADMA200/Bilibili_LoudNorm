# 测试说明

本项目的验证分三层。**随仓库发布的只有第一层（纯 Node 单元套件）** —— 因为它零依赖、任何人 clone  
下来就能跑；另外两层依赖本机 headless 浏览器与**已登录的 B 站 profile**，他人无法复现，故不随仓库发布，仅在此记录**跑法**与**结论**。

---

### 另有一道构建期守卫

```bash
node build.mjs
```

构建时会扫描产物，确认**没有出现任何干预播放器的调用**：`video.pause()` / `preventDefault()` /  
`alert()` / 无参 `disconnect()`。命中即构建失败（`铁律守卫失败`）。这是本项目最核心的设计约束。

同时构建会产出两个文件（发布版剥注释 / 开发版全留），并用 `node --check` 真实解析一遍两版产物 ——  
剥离注释是逐字符扫描实现的，一旦把正则误判成注释就会删掉真代码，**语法自检是这条链路的兜底**。

## 二、端到端验证（❌ 不随仓库发布）

**为什么跑不了**：需要**已登录的 B 站浏览器 profile**（会员集、番剧链路都要登录态），  
再加上本机 headless 浏览器 + CDP 调试端口。别人 clone 下来没有登录态，必然失败。

### 跑法（供参考）

```bash
# 1. 起一个带调试端口的独立无头浏览器（用登录态 profile 的副本，别动日常实例）
"/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge" \
  --headless=new --no-sandbox --disable-gpu --disable-dev-shm-usage \
  --remote-debugging-port=9222 --user-data-dir=/tmp/bl_edge_profile \
  --no-first-run --no-default-browser-check about:blank &

# 2. 跑验证（注意：CDP 端口要给两处 —— 脚本里 HTTP 基址在模块加载时求值）
CDP_PORT=9222 node probe/s3-panel-verify.mjs Bilibili_LoudNorm.user.js probe/raw/out.json 9222
CDP_PORT=9222 node probe/s2-verify.mjs     Bilibili_LoudNorm.user.js probe/raw/out.json
```

> ⚠️ 两个坑：① `--no-sandbox` 是必须的，否则 Chromium 自身的沙箱初始化会被拒  
> （`sandbox initialization failed`）；② 只传末位参数端口无效，必须同时给 `CDP_PORT` 环境变量。

## 三、一次性取证脚本（❌ 不随仓库发布）

`probe/bl_*` 与 `probe/s3-*-probe.mjs` 是开发期的摸底/取证脚本（例如：确认 B 站播放器  
`loudnessSwitch` 的默认值、番剧 SSR 与接口的 `data` 形状差异），**跑完即弃**，输出落在 `probe/raw/`。  
它们是 `docs/B站响度归一-方案与实测.md` 中各条结论的原始证据来源，但对读者是噪音，故不发布。

`probe/raw/` 里的原始输出**含真实账号指纹**（B 站 UID、设备指纹），已列入 `.gitignore`，绝不公开。
